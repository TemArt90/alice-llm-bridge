# Личное подключение Алисы к OpenCode Go

Это отдельный **разговорный** навык «Спроси Ерёму», а не расширение умного дома.
В навыке установлен универсальный голосовой промпт без тематической привязки: короткие понятные ответы, помощь в вопросах и делах, идеи и обсуждение решений. По стилю он похож на Hermes, но не получает инструменты Hermes, доступ к интернету или управление устройствами.
OpenCode Go предназначен для coding agent traffic: https://opencode.ai/docs/go .
Не маскируем произвольный чат под OpenCode CLI; клиент сообщает собственный User-Agent.

## Проверенный статус

- Приватный навык называется «Спроси Ерёму»; в кабинете доступна опубликованная версия:
  https://dialogs.yandex.ru/developer/skills/50e5bf26-dd9f-481c-872a-356b21c96569/draft/test
- Аккаунт владельца добавлен в allowlist. Оба режима (`fast`, `smart`) используют `deepseek-v4.1-flash` через OpenCode Go; GLM больше не выбирается.
- Пройдены 84 Python-теста, включая проверку, что прокси применяется только к Cloudflare, а запросы модели остаются прямыми. Ранее пройдены 13 тестов неизменённого Worker.
- После смены промпта через публичный webhook задан бытовой вопрос о прогулке в дождь: получен совет взять зонт или дождевик и подходящую обувь, без отказа из-за темы. История сохранена. Отчёт: `verification-persona.json`.
- Публичная сквозная проверка постоянной службы после 65 секунд простоя пройдена: посторонний пользователь отклоняется, профиль распознаётся, вопрос доходит до DeepSeek, отложенный ответ возвращается на «ну что». Все запросы проверки вернули HTTP 200 в пределах 4,5 секунды. История не удалялась. Отчёт: `verification-end-to-end.json`.
- В настоящем тестере Яндекса задан вопрос про индекс SQL и получен ответ: «Индекс в SQL нужен, чтобы база быстрее находила нужные строки, не перебирая всю таблицу целиком».
- **Пользователь подтвердил физическую проверку:** колонка запустила навык и ответила. Это подтверждение владельца, а не удалённое прослушивание агентом.
- Постоянная служба использует `run_service.py`, автозапуск включён, `Linger=yes`. Локальный Xray также включён и настроен на автозапуск.

### Сетевой маршрут

Прямое соединение Ubuntu с Cloudflare показывало повторяющиеся тайм-ауты. Обмен `/_agent/poll` и `/_agent/result` переведён на существующий локальный HTTP-прокси Xray (`relay_proxy_url` в личном `settings.json`). С этим маршрутом пройдены публичный тест, настоящий чат Яндекса и проверка колонкой.

Квота Cloudflare считается на аккаунт: бесплатный тариф даёт 13 000 GB-s
времени жизни Durable Object в сутки (сброс 00:00 UTC). Двухсекундный
long-poll держал объект активным круглосуточно и выедал её за сутки, после чего
Worker отвечал 500 `error code: 1101`. Поэтому добавлен WebSocket-транспорт
(`/_agent/ws`): объект засыпает в простое, квота тратится только на реальные
команды. Включается строкой `"relay_transport": "websocket"` в `settings.json`;
резервный путь `/_agent/poll` остаётся, переключение обратимо. Та же квота
обслуживает навык люстры в `zhi_guang`.

Прокси применяется явно только в облачных операциях. Модель OpenCode Go и локальный Rust-сервер не направляются через него. Глобальные настройки прокси и настройки люстры не менялись. Точный механизм обрывов прямого маршрута не установлен; приписывать их конкретному провайдеру или блокировке без отдельной диагностики нельзя.

Зелёный `/health` Worker сам по себе не доказывает связь с Ubuntu. Для проверки всей цепочки:

```sh
cd ~/alice-llm-bridge/local-deploy
.venv/bin/python verify_end_to_end.py
```

Проверка добавляет короткий технический вопрос, но не очищает историю и не переключает модель. Старый `probe_public.py` также больше не отправляет команду удаления истории.

### Изолированное окружение Ubuntu

Сервис использует `local-deploy/.venv/bin/python`, а не системный Python. Установка:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

Системный Brotli 1.1.0 несовместим с aiohttp 3.13.4: распаковка реальных заданий падает с `TypeError: process() takes exactly 1 argument (2 given)`. В отдельном окружении установлен Brotli 1.2.1; регрессия покрыта `test_runtime.py`. Ошибка распаковки исправлена отдельно от сетевого маршрута; успешность всей цепочки проверяется сквозным тестом, а не одним тестом сжатия.

Смена темы запроса на программирование и собственный User-Agent сами по себе не гарантируют соответствие правилам OpenCode Go. Документация требует типичный трафик coding agent; универсальный голосовой чат не следует считать автоматически разрешённым.

## Раскладка и выкатка

Код правится в Windows-копии (`H:\workspace\alice-llm-bridge\local-deploy`), а
работает Ubuntu-копия в `~/alice-llm-bridge/local-deploy`. Поэтому после правок
`sidecar.py` (и `worker.js`, если нужна паритетность копий) файлы копируются на
Ubuntu, затем:

```bash
systemctl --user restart alice-code-sidecar
```

Сам Worker публикуется только из Windows:

```powershell
python deploy_worker.py --update      # изменить существующий
python deploy_worker.py --verify      # прочитать и проверить
```

Служба живёт в user-scope systemd (`~/.config/systemd/user/`), `Linger=yes`
включён, поэтому переживает выход из сессии. Проверять состояние нужно через
`systemctl --user`, а не системный `systemctl` — системный ответит `not-found`
для работающей службы.

## Схема

Колонка → HTTPS Cloudflare Worker → исходящий WebSocket с домашней Ubuntu →
(резерв — HTTP polling) →
оригинальный Rust alice-llm-bridge → локальный адаптер → API OpenCode Go.
История — отдельная PostgreSQL. Навык люстры, его Worker и настройки не меняются.
Входящие порты роутера не открываются.

- Исходники: https://github.com/eluceon/alice-llm-bridge (MIT).
- Контейнер закреплён на digest `sha256:56ec78513a1e6b10a16d6c88184f044aaec9586ea5f56b4f3a92de2a18ca8d4b`.
- Bridge: `127.0.0.1:18090`; Go-адаптер: `127.0.0.1:18091`; PostgreSQL: `127.0.0.1:15434`.
- Рабочая папка Ubuntu: `~/alice-llm-bridge/local-deploy`.
- `config.toml`, `secrets.json`, `settings.json`, `*.env` — личные данные, не коммитить.
- Модель обоих режимов: `deepseek-v4.1-flash`; рассуждения отключены для коротких голосовых ответов.

## Проверка Python-адаптера

Из корня репозитория:

```text
hermes verify local-deploy --phase test --timeout 120
```

Манифест `local-deploy/.hermes/environment.json` запускает все Python-тесты через `uv`, Python 3.11 и зависимости из `requirements.lock.txt`. Это отдельная проверка адаптера, а не успешная сборка всего Rust/Docker-проекта; результат регистрируется с ограниченной областью (`targeted`). Корневой `make build` остаётся без изменений.

## Приветствие при запуске

Настраивается в личном `local-deploy/settings.json`:

```json
"greeting_text": "Привет! Я Ерёма. Чем могу помочь?"
```

На Ubuntu это `~/alice-llm-bridge/local-deploy/settings.json`. После изменения перезапустите `alice-code-sidecar`. Допустима непустая строка не длиннее 1000 символов.

Исходная фраза всё ещё остаётся в неизменённом Rust-образе (`crates/bridge-server/src/routes.rs`, `GREETING`). Адаптер заменяет её в `text` и `tts` только после проверки доступа, при новой сессии и пустой входной реплике. Для постороннего пользователя сохраняется исходный отказ. Проверены оба пути адаптера и публичный HTTPS webhook; отчёт `verification-greeting.json`.

## Режим рассуждения

Для `deepseek-v4.1-flash` адаптер явно передаёт `thinking: {"type": "disabled"}` в обоих режимах. «Умный» режим сейчас отличается лимитом длины ответа, но не включает thinking. Фраза «мне нужно немного подумать» — стандартная заглушка моста, когда ответ API не успел к сроку webhook; она не сообщает состояние режима рассуждения модели.

## Команды на Ubuntu

```sh
cd ~/alice-llm-bridge/local-deploy
docker compose ps
systemctl --user status alice-code-sidecar
journalctl --user -u alice-code-sidecar -n 30 --no-pager
curl -fsS http://127.0.0.1:18090/health
curl -fsS http://127.0.0.1:18091/health
```

Перезапуск: `docker compose up -d` и `systemctl --user restart alice-code-sidecar`.
Остановка: `systemctl --user stop alice-code-sidecar` и `docker compose stop`.
Не применять `docker compose down -v`: это удалит историю разговоров.

## Голосовые команды

- «Алиса, запусти навык Спроси Ерёму».
- «Объясни, зачем нужен git rebase».
- «Переключись на умную модель» / «Смени модель на быструю».
- «Подумай как следует, [вопрос по разработке]».
- «Помни последние 5 реплик» / «Забудь всё».
- Если ответ не успел: «Ну что?».
- Для выхода из навыка используйте штатную команду Алисы «Хватит».

## Важные ограничения

Колонка не меняет свою основную модель: OpenCode доступен только внутри навыка.
Модель здесь не имеет инструментов, не читает файлы и не выполняет команды.
Основные ответы короткие; длинный ответ может быть сокращён для озвучивания.
Исходный мост использует отложенные ответы: если модель не успела, нужно спросить ещё раз.
История и выбранная модель привязаны к профилю оригинального моста; настроен один взрослый профиль.
Адаптер отправляет стабильный `x-opencode-session` для этой установки.
Публичный секретный webhook защищён дополнительно списком разрешённых пользователей Яндекса.
Доступ привязан к аккаунту владельца через непустой `allowed_user_ids`; временный `setup-locked` удалён.
Файл `config.toml` на Ubuntu возвращён в режим 0400 после настройки.

Счётчик «сколько потратили» исходного моста — **приблизительная оценка** по входным
и выходным токенам, не дополнительный платёж и не точный остаток подписки. Он не учитывает
все особенности кэша Go. Точные allowance/лимиты/Extra Usage смотрите в консоли OpenCode.
Мост обращается только к `/inference/go/…`, но глобальная настройка Extra Usage в аккаунте
может разрешить расход оплаченного баланса после исчерпания лимита. Автоматически её не меняли.

Постоянная работа требует включённой Ubuntu, сети и доступности Cloudflare/OpenCode.
На Ubuntu при установке было меньше 2 ГБ свободного места: нужно отдельно решить вопрос
с запасом диска. Сборку Rust на сервере не запускаем, используем готовый небольшой образ.
